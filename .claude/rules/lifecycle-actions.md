## lifecycle-actions

**RULE**: The actions on something staff author and members see (publish, unpublish, duplicate, delete, reset to published, bring a version back, history, preview) come from one registry, `src/lib/lifecycle-actions.ts`: each has one icon, one label and, where it needs one, one confirmation. Render them with `src/components/LifecycleButton.tsx` (`<LifecycleButton action="delete" noun="page" title={page.title} onRun={...} />`, `variant="icon"` for a row of icon buttons) and show state with `src/components/LifecycleStatusChip.tsx`. Don't write a "Publish" or "Delete" button with its own icon, wording or `confirm`: a new one means a new entry in the registry. Landing pages and courses both use it; so should the next thing that is published.

- **The registry is the wording.** Labels, the confirm title ("Take this page down?"), body and confirm button live there, following `confirmations.md` (title a question, body says what happens and whether it can be undone, the confirm button names the action). Where a place needs a detail only it knows ("It comes off the public site at once."), pass it as `detail`; don't copy the rest of the sentence. A text control that must read longer ("Publish changes") overrides `label`, nothing else.
- **Menus and links** that can't be a `LifecycleButton` (an `ActionMenu` item, a `Link` to preview) take their icon and label from `lifecycleIcon(action)` and `lifecycleLabel(action, noun)`, and a delete asks with `lifecycleConfirm("delete", {...})` in a `ConfirmDialog`.
- **Not every thing has every action.** Only a landing page keeps a draft apart from what is published, so only it has reset, bring back and history. A course's "draft" means members can't see it; it has no draft copy of its content and no versions. Don't add a reset to a thing that edits live; add the action to the registry only when something has the behavior.
- **Publishing that needs a check first** (the landing page's accessibility check, the course import's blockers) keeps its own dialog; it still uses the registry's icon, and the status chip.
- **Status**: `LifecycleStatusChip published={...}` is the only "Draft / Published" pill. Reasons a thing is hidden go beside it as text.
- **Adding an action**: add the icon meaning to `src/components/Icon.tsx` if it has none (`icons.md`) and the entry to `LIFECYCLE_ACTIONS`. `tests/lib/lifecycle-actions.test.ts` then checks its wording against `confirmations.md` (question title, button repeats the control's label, danger tone) and that no two actions share a picture; add the action to the list of ones that ask there if it does.
