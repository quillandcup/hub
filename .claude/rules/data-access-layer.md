### Data Access Layer (repositories)

**RULE**: A table that has a repository in `src/lib/data/` is queried only through it: no `.from("<table>")` in pages, actions, routes or other lib code. Which tables have which repository, and the rules specific to each (secrets that never reach a log, the caller's RLS client, service-role-only reads), is the catalog in `docs/architecture/DATA_ACCESS_LAYER.md`: read the repository's entry before changing its queries. `tests/lib/data-access-layer.test.ts` fails on a new direct query and lists the files still to move (an allowlist that only shrinks; remove a file's line when you move its queries). It parses the source (not a text search): a direct `.from("x")` on a table that is neither registered nor in `UNMIGRATED_TABLES` fails, so a new table needs a repository from the start, and so does a `.from(variable)` outside the few files listed with a reason.

- **One interface per aggregate, two implementations.** `AttendanceRepository` is what callers depend on; `SupabaseAttendanceRepository` runs the queries (typed with `Db`, i.e. `SupabaseClient<Database>` from `src/lib/data/database.types.ts`), `InMemoryAttendanceRepository` is the twin for tests, demos and typed seed data. `createRepos(db)` (`src/lib/data/repos.ts`) builds them over one client; `getRepos()` (user, RLS, sudo header) and `getServiceRepos()` (service role) are in `src/lib/data/server.ts`. The client you pass decides the privilege.
- **Callers take the repository, not the client**, so their tests pass the in-memory twin instead of faking PostgREST call shapes. Leaf lib functions take `attendance: AttendanceRepository`; big functions that still take a `supabase` client build `createRepos(supabase)` inside until they are converted.
- **Business rules live in the repository once**: distinct prickles vs. attendance records, pagination past 1000 rows (with a stable `.order("id")`), id chunking for `.in(...)`. Methods return domain-shaped data (`Set`, `Map`, `AttendanceLink`), not PostgREST rows, and throw on a database error instead of returning an empty result.
- **Joins are the repository's job.** A method returns the shape the use case wants with the other table already joined in (`PrickleDetail` is a prickle with its `type` and `host`); the Supabase class runs the PostgREST embed and maps it, the in-memory class joins from a shared `InMemoryDataset` (`src/lib/data/in-memory.ts`: members, prickle types, prickles, attendance). Build a dataset and `createInMemoryRepos(dataset)` in a test, or as a typed seed profile; `vi.mock("@/lib/data/repos")` to hand it to code that calls `createRepos`. Never write a PostgREST embed (`prickle_types(name)`, `host:prickle_host(...)`) outside `src/lib/data/`.
- **Shared helpers, no base class.** `src/lib/data/query.ts` has what every repository needs (`Page`/`PageQuery`/`asPage`, `must`, `inChunks`, `sortByKey`, `byKeyThenId`, `upsertInChunks`); pagination is `fetchAllRows` and `chunk` in `src/lib/supabase/paginate.ts`. Don't define these per file; bulk Bronze writes go through `upsertInChunks`, never a string-table helper like `upsertInBatches` (the guard flags a registered table passed to it).
- **Errors and misses.** A lookup that finds no row returns `null` (or an empty collection) and the *caller* picks the user-facing message. Repositories throw `new Error(error.message)` with the database's message for logs and never put PostgREST text in front of users.
- **Both implementations pass one contract suite** per repository (`tests/helpers/*-contract.ts`, run by `tests/lib/data/` against the twin and `tests/api/data/` against the real database). A new method goes in the interface, both classes and the contract.
- **Auth accounts are a repository too, though not a table.** Supabase Auth's admin API (`<client>.auth.admin`: list, create, invite, ban, delete, sign-in links) is reached only through `AuthUserRepository` (`src/lib/data/auth-users.ts`, `repos.authUsers`, service role only: the admin API refuses a user client). `all()` pages past the API's 1000 per page; a route that called `listUsers` itself silently dropped every account after the first thousand. It returns Hub's `AuthUser` (`bannedUntil`, `confirmed`, `appMetadata`), not GoTrue's `User`; the twin reads `InMemoryDataset.authUsers`; `generateMagicLink` takes an account id because the admin API's `generateLink` creates an account for an address it does not know. `tests/lib/data-access-layer.test.ts` fails on any `.auth.admin` in `app`, `lib`, `components` or `scripts`.
- **Adding a repository**: interface + Supabase class + in-memory class in `src/lib/data/<aggregate>.ts`, add it to `Repos`/`createRepos`, a contract suite run both ways, and add the table to `REPOSITORY_TABLES` in the guard test with the files still querying it.
- **Types**: `pnpm types:gen` regenerates `src/lib/data/database.types.ts` from the local database after a migration (`supabase start` with all migrations applied, Docker running); commit the result. It runs the Supabase CLI version pinned in `package.json` (via `npx`), which `tests/lib/supabase-cli-version.test.ts` keeps equal to `SUPABASE_CLI_VERSION` in CI, because the generator formats its output differently between versions: bump both together. CI's `Test (db) & build` job runs `pnpm types:check` (regenerate, fail on any diff), so a migration without regenerated types fails the PR. `Row<"table">` from `src/lib/data/db.ts` gives a row type. **Every Supabase client is typed** with `Database` (`src/lib/supabase/server.ts`, `service.ts`, `client.ts`, `api-auth.ts`, the proxy's client, and the few routes that build their own), so a misspelled column, a nullable value for a NOT NULL column, or an RPC no migration creates fails `pnpm typecheck`; `tests/lib/typed-supabase-clients.test.ts` fails on a client created without `<Database>`. Use `Insert<"table">` / `Update<"table">` (`src/lib/data/db.ts`) for payload objects built in pieces, and `asJson(value)` (`src/lib/data/json.ts`) for a vendor payload stored whole in a `jsonb` column. When the generated type is stricter than the database (a column the DB defaults, a trigger-filled `canonical_email`, an RPC argument that accepts null), cast at that one call with a comment saying why; don't loosen the client.
