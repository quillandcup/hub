## icons

**RULE**: Icons come from `components/Icon.tsx`: `<Icon name="edit" />`. It is the one set, drawn by `lucide-react`, with one name per *meaning* (edit, delete, preview, duplicate, copy link, reset...), so the same action has the same icon in every list, builder and editor. Don't import from `lucide-react` in a page or component, and don't paste an inline `<svg>`: `tests/lib/icons.test.ts` fails on both in `app` and `components`.

- **Need a meaning that isn't there?** Add it to `ICONS` in `components/Icon.tsx` with the lucide icon that says it (https://lucide.dev/icons). Name it for what it means, not what it looks like (`reset`, not `rotate-ccw`), and give two meanings two pictures (the Icon test fails on a duplicate). An existing meaning keeps its icon: `edit` is a pencil everywhere; don't pick a second icon for it.
- **Globe means visible to others, lock means only you (or staff).** Published, public and "on my profile" are the globe; unpublished, draft, private and "only me" are the lock (`publish` and `unpublish` in `Icon.tsx`). The writing visibility toggles (`components/writing/VisibilityToggles.tsx`) already use 🌐 and 🔒 for the same two meanings; keep them aligned, and don't use an eye-off or a different icon for "not public".
- **Undo is not reset.** Step-by-step undo/redo is an arrow that goes back one edit; "reset to published" (`<LifecycleButton action="reset">`, see `lifecycle-actions.md`) is the loop that throws the draft away. Keep them visibly different.
- **An icon-only control needs its own name.** `Icon` is `aria-hidden`, so the button carries `aria-label`, and a `<Tooltip content="...">` around it for the hint (never a native `title`: `.claude/rules/tooltips.md`; the confirm dialog, not a visible label, is what guards a destructive one). `InfoTip` is for a definition that needs text, not for naming an icon.
- **Size and color** come from `className` (`h-4 w-4` by default, text color), never an attribute on the glyph.
- **A custom drawing is not an icon**: a chart, graph or progress ring, and a brand mark (a Slack or Google logo) lucide doesn't have. Those stay inline SVG, listed in `CUSTOM_DRAWINGS` in the guard test with the reason.
- **Existing files** that still import lucide directly or hold an inline icon are in the test's baseline (`LUCIDE_BASELINE`, `SVG_BASELINE`). Convert them as you touch them and remove the entry: the test fails on a stale entry, and on a file that has *more* inline SVGs than its baseline, so the list only shrinks.
