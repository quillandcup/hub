## tests-with-every-change

Every change that adds or alters behavior ships with tests, in the same PR. CI gates new code on it: `scripts/coverage-report.ts --patch-base` requires `MIN_PATCH_SCORE` (80%) of the added lines to be covered by the combined unit + db suites, and the `Coverage report` check is required to merge. Finding that out from a red CI run costs a round trip; write the tests first.

- **Add tests before opening the PR**, not after CI fails. New route handler, server action, lib function or component: it gets a test of its own, in the folder that matches (`tests/api/`, `tests/components/`, `tests/components/pages/`, `supabase/tests/database/` for RLS and SQL functions). "Covered indirectly by another test" doesn't count unless you checked the coverage.
- **Run them locally** (`pnpm test:unit`, plus `pnpm test:db` or `pnpm test:pgtap` when you touched SQL) and `pnpm typecheck`. Don't hand back work as done on a green build alone, and don't claim tests pass without running them. If CI already passed and you only need a check CI covers, say so instead of re-running.
- **Test behavior**: render and interact for components, call the handler for routes, assert the outcome. Cover the failure and edge paths you added (unauthenticated, empty, over 1000 rows), not just the happy path.
- **Bug fixes** start with a test that fails without the fix.
- **`skip-patch-coverage` needs human approval, every time.** It's a last resort, only for lines that can't be hit (defensive branches, framework glue). Never add the label yourself, and an earlier approval on another PR doesn't carry over. Ask the user, with the specific lines and why they can't be covered; only after they say yes, add the label *and* a PR comment recording the reason. Never use it because a test is tedious. Never lower `MIN_PATCH_SCORE` or an `AREA_FLOORS` entry, or skip, loosen or delete a test to get green (see `pr-watch.md`).
- The existing requirements in `CLAUDE.md` (reprocessability, idempotency, pagination tests for the data pipeline routes) still apply on top of this.
